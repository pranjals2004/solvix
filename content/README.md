# Content imports

`templates/import.example.json` shows the JSON shape; replace its placeholder UUIDs with IDs from `/api/v1/subjects` and `/api/v1/subjects/:subjectId/topics`. `templates/questions.csv` and `templates/notes.csv` contain the supported CSV headers. JSON records use UUIDs; CSV records use the subject and topic slugs from those same endpoints. CSV JSON-valued cells (`optionsJson`, `correctAnswerJson`) must be quoted valid JSON.

An administrator imports either representation at `POST /api/v1/admin/import`. Each request accepts up to 100 questions and 100 notes; notes and worked solutions are chunked and embedded by the ML service before the database transaction starts. If embedding fails, the import is rejected and its content rows are not written. Supplying an existing UUID updates that record, making repeat imports possible.

For practice grading, store MCQ answers as an option label (`"A"`) or `{ "selected": "A" }`, MSQ answers as a list of labels, NAT answers as a number or numeric string, and short answers as text. Short-answer grading ignores case and repeated whitespace but otherwise requires the stored wording. The mobile client submits the learner's answer and required 1–5 confidence rating to `/api/v1/submissions`; the API returns the correct answer and solution only after that attempt.

Run `npm run db:seed` after migrations and start the ML service first. It adds ten original, clearly labelled demo multiple-choice questions for each core subject, with answer options, grading keys, and short worked solutions. It also imports `import/Solvix_data.csv`: the source contains questions and answers but no options or worked steps, so those rows are shown as short-answer draft questions and remain clearly labelled for review. None of these are authentic GATE PYQs or instructor-reviewed material. The seed keeps deterministic IDs so rerunning it updates the same rows. No performance or accuracy results are included.
